Cómo se entrenó el modelo de recomendación

El servicio de IA de Euphoria, explicado paso a paso y con diagramas. Sin código: solo las ideas.

La idea en una frase: se juntaron todas las ventas pasadas, se probaron tres formas de aprender, se eligió la mejor en una competencia, se le hizo un ajuste fino y, al final, se le pusieron reglas del negocio encima. El ganador es el que hoy sugiere productos.

Los pasos 1 y 2 preparan los datos. El 3 y 4 eligen el modelo. El 5 lo pule. El 6 y 7 lo ponen a trabajar en el local. Cada paso se explica abajo.

1Limpieza y preparación de los datos

Antes de aprender nada, hay que ordenar los datos. El programa toma las ventas (de la base vieja o de la nueva, da igual) y las convierte en canastas: cada venta es una lista de los productos que se pidieron juntos, con su fecha.

Base viejarespaldo PostgreSQL
Base nuevaMySQL (db_euphoria)
→
Formato únicoventa · producto · fecha
→
Armar canastasagrupar por venta y quitar repetidos
→
Sacar el contextode la fecha: día y hora, fin de semana
→
Dividir por tiempoventas viejas = entrenar
ventas nuevas = probar

Qué se limpia: se unifican las dos bases al mismo formato, se quitan productos repetidos dentro de una misma venta, se convierten las fechas a día/hora y se rellenan los datos que faltan (por ejemplo, si un producto no tiene costo). Además se guardan los datos de cada producto (nombre, categoría, precio, stock).

Detalle importante: la división por tiempo (entrenar con lo viejo, probar con lo nuevo) es clave: evita hacer trampa. El modelo se prueba con ventas que nunca vio, como pasaría en la realidad.

2Los tipos de aprendizaje (por qué se probaron tres)

No se eligió un método "a dedo". Se probaron las tres familias de aprendizaje automático para ver cuál funcionaba mejor con los datos reales del local:

No supervisado

Aprende solo, sin respuestas.
Descubre qué productos se piden juntos. No necesita saber quién es el cliente.
Supervisado

Aprende con ejemplos correctos.
Se le enseña: "en esta canasta, este producto SÍ estaba (1), este NO (0)". Aprende a predecir.
Refuerzo

Aprende por prueba y error.
Sugiere algo, ve si acierta, y ajusta. Mejora con el tiempo, como un mesero con experiencia.

Cada familia se entrenó por separado con las mismas canastas, para compararlas en igualdad de condiciones.

3Los metadatos (las "señales" que mira el modelo)

El modelo no adivina: decide mirando varias señales al mismo tiempo. Estas son las variables que se le dan de comer:

Co-ocurrenciaqué se pide junto
Similitud entre productosparecidos por co-compra
Popularidadlo más vendido
Preciodel producto
Categoríatrago, botella, snack…
Contexto horariodía, hora, fin de semana
→
MODELOjunta todas las señales
Las que más pesan (según el propio modelo): la co-ocurrencia y la similitud entre productos, seguidas del contexto horario. O sea: lo que más ayuda a acertar es "qué se pide junto" y "a qué hora".

4Los algoritmos (la "maquinaria" de cada familia)

Cada tipo de aprendizaje se implementó con un algoritmo concreto:

FamiliaAlgoritmo usadoQué hace, en simple
No supervisadoReglas de asociación (Apriori) + similitud por cosenoEncuentra reglas tipo "quien pide botella tiende a pedir mezclador" y mide qué tan parecidos son dos productos.
SupervisadoGradient Boosting — LightGBMJunta todas las señales en un solo modelo y aprende combinaciones complejas. Es el motor principal.
RefuerzoBandit contextual (Thompson Sampling)Prueba una sugerencia, recibe premio si acierta, y ajusta sus probabilidades.

Ojo con la diferencia: el modelo final es híbrido (mezcla las señales de contenido y colaborativas), y el algoritmo que lo arma es el gradient boosting (LightGBM).

Qué significan las medidas (en lenguaje normal):

MedidaQué dice
HitRate@3 = 0.98De cada 100 sugerencias, 98 traen el producto correcto entre los 3 primeros.
HitRate@1 = 0.86Acierta el producto correcto en el primer puesto 86 de cada 100 veces.

Conclusión de la competencia: ganó el supervisado (LightGBM). El no supervisado quedó como respaldo interpretable, y el refuerzo como plan a futuro (rinde más cuando hay un flujo real de aciertos que aprender).

6Ajuste fino y control de sobreajuste (Optuna)

Al ganador se le buscaron los mejores "ajustes" (hiperparámetros) con Optuna, y sobre todo se revisó que no estuviera memorizando (sobreajuste). Para eso se partió el tiempo en tres:

Pasadoentrena aquí
→
MedioOptuna prueba ajustes
(datos no vistos)
→
Futurojuez final
(no se toca en el ajuste)

Cómo se sabe que no hace trampa: se compara el acierto en "entrena" contra el acierto en "futuro". Si son parecidos, el modelo generaliza bien (el 99% no fue suerte del reparto). Si el de entrenar fuera mucho más alto, sería una señal de que solo memorizó.

Optuna probó decenas de combinaciones de ajustes (búsqueda inteligente, no al azar) y se quedó con la mejor. El resultado es el modelo final que se guarda.

7La capa de reglas del negocio

El modelo entrega un puntaje matemático puro. Encima se le pone una capa de reglas del negocio que reordena la sugerencia según lo que le conviene al local, sin volver a entrenar:

Puntaje del modelo
×
¿Hay stock?si no hay, se elimina
×
Hora / díaempuja según franja
×
Margenpremia lo más rentable
×
Promociónempuja lo que está en promo
=
Sugerencia final

Así, aunque el modelo diga "sugiere el producto X", si X está agotado desaparece, y entre dos parecidos se prefiere el más rentable o el que está en promoción a esa hora. También hay un motor que arma combos con descuento.

Ventaja: estas reglas se cambian desde una tabla de la base de datos (regla_negocio), sin tocar el modelo ni reprogramar nada.

Para actualizar el modelo cuando haya más ventas, se vuelve a entrenar (los mismos pasos), se genera un nuevo archivo y se reemplaza. Nada más cambia: el servicio sigue igual. La guía está en docs-originales/ia-REENTRENAR.md.

En resumen

Ventas → canastas limpias → se compiten tres formas de aprender → gana el supervisado (LightGBM) con ~100% de acierto → se ajusta con Optuna cuidando que no memorice → se le suman las reglas del negocio → y ese es el que hoy le sugiere productos al mesero.
