El frontend, a detalle

Las pantallas que usan las personas, por rol, y cómo el frontend habla con el backend. Para que puedas explicar cada parte.

Qué es: una aplicación Vue 3 + Vite. No tiene la lógica del negocio: solo muestra pantallas y le pide todo al backend. Son 56 pantallas organizadas por rol.

0. Cómo funciona por dentro (la mecánica)

Cuatro piezas hacen que todo funcione. Esto es lo que conviene tener claro:

PiezaQué hace
main.jsArranca la app de Vue, enchufa el enrutador y las tiendas.
servicios-api/cliente-http.jsLa conexión al backend (axios, base /api). Le pega el token a cada petición automáticamente. Si subes un archivo (imagen), acomoda el envío para que llegue. Y si tu sesión vence, la renueva sola; si no puede, te manda al login.
composables/useTiempoReal.jsLa conexión de tiempo real (Socket.io). Una pantalla se "suscribe" a lo que le importa (por ejemplo eventos, aforo) y cuando el backend avisa que eso cambió, la pantalla se actualiza sola.
enrutador/index.jsDecide qué pantalla mostrar según la dirección, y controla el acceso por rol: si no iniciaste sesión te manda al login, y si intentas entrar a un área que no es de tu rol, te muestra un aviso y te devuelve a la tuya.

El estado global (las tiendas/, con Pinia) guarda lo que se comparte entre pantallas: la sesión (tienda-autenticacion: quién eres, tu rol, tu token), el carrito (tienda-carrito) y los avisos (tienda-notificaciones).

Resumen para dominarlo

Cada pantalla pide datos con un servicio-api (que ya le pega tu token), guarda lo compartido en una tienda y escucha los cambios en vivo con useTiempoReal. El enrutador decide qué ves según tu rol y no te deja entrar donde no te corresponde. Si te preguntan por el frontend, respondes: "es Vue, no tiene lógica de negocio, cada rol tiene sus pantallas, habla con el backend por HTTP con el token, y se actualiza en vivo con Socket.io."
